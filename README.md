# トロロの街 (prototype)

街の管理人・工房の店主としてコザクラインコたちの暮らしを眺める箱庭シム。Expo SDK 54 (React Native) + TypeScript。Expo Go(SDK 54対応版)でそのまま実機確認できます。

プレイヤーは鳥を直接操作しません。中央の街と周囲のフィールド(敵・採掘資源・お宝)を、仲間になった鳥たちが各々の意思で歩き回ります。**素材・お金はまず鳥個人の所有物になり**、プレイヤーは街の管理人・商人として、鳥から素材を買い取ったり、依頼掲示板で欲しい素材を発注したりして、街の共有資源(倉庫)を少しずつ蓄えます。

## ゲームループ

0. **スタート時の鳥選択**: ゲームを初めて開始すると、ビビ・ハク・トロロ・モネの4羽から一緒に街を始める1羽を選ぶ選択画面が表示される(役割・性格が伝わる紹介文付き)。選んだ1羽だけが最初から街にいる状態でゲームが始まり、街の役場も「ボロ役場」(🛖)として表示される。残り3羽は`isRecruited: false`のまま、マップにもステータス画面にも表示されず、AI行動も一切しない——ただしそれぞれ専用の加入トリガーを常時チェックしており(`game/recruitment.ts`)、条件を満たすと自動的に仲間になり、その場で「🎉 新しい仲間!」の簡単な演出(アバター+一言セリフ)が表示される。1度でも1羽を選ぶと、以後は常に街の画面が表示される。
   - 🟡 ビビ: 街レベル到達(役場が「村役場」🏘️になる程度=街の発展ポイントが60pt。土地解放1回で30pt入るので、土地を2区画解放すればほぼ到達——`data/townGrid.ts`のgetTownLevel)。
   - 🩵 ハク: 専用クエスト「初めての採取に成功する」を達成(自由行動・依頼どちらの採取でも可。`useQuestStore`に一度だけ記録される)。
   - 🟢 トロロ: マップ探索中の偶然の出会い。フィールド上の特定地点(❓マーカーで示唆)に活動中の鳥が近づくと、低確率で毎ティック抽選される。
   - ✨ モネ: トロロと似た仕組みの別地点での偶然の出会い、またはオオカミ級の敵を初めて討伐すると即座に加入(どちらか早い方)。
1. **街とフィールド**: マップ中央に街、その周りに森・鉱山・キノコ畑・湖・遺跡といった自然な区画があり、それぞれのエリア専用の素材(森=木材/木の実/薬草/羽根、鉱山=鉱石/宝石/石炭、キノコ畑=キノコ、湖=魚/真珠/水草、遺跡=遺物/魔石/古いコイン)が手配置される、常設の1つのマップ(ステージ制ではない)。街の周囲には木や花の装飾も配置される。
2. **個体AI(性格は重み付け、絶対ではない)**: 仲間になった鳥はそれぞれ独立したAIで行動する(1つの群れとして固まらない)。戦闘・採掘・探索・休憩のどれも全員が行いうるが、性格によって選ばれやすさと危険地帯への忌避度が変わる。
   - 🟢 トロロ(vanguard): 戦闘・探索に大きく偏るが、採掘や休憩もする。危険は気にしない。
   - 💛 ビビ(clingy): 休憩・探索を好むが、戦闘や採掘もする。危険は苦手。
   - 🩵 ハク(cautious): 休憩に大きく偏るが、危険度の低い相手となら普通に戦う。
   - ✨ モネ(freeSpirit): 採掘・お宝回収に大きく偏るが(納品+20%)、資源が無ければ戦闘や探索もする。
   - 敵と遭遇した際の戦闘選択率は、その敵の強さ(攻撃力)と各鳥の危険忌避度に応じて下がる(弱い敵ならほぼ誰でも戦う)。
   - 複数の鳥が重なりそうになると、毎ティック軽く押し合ってすれ違う(`separateBirds`)。
   - 敵自身も自分の縄張り(スポーン地点周辺)をランダムに徘徊し、近くに鳥を見つけると追跡する。見失ったり離されすぎたりすると縄張りへ引き返す(`game/enemyAi.ts`)。追跡中の鳥が街エリアのゾーン境界(`getTownZoneRadius`)の内側に入った時点でも追跡を諦める——街を「安全地帯」として扱い、敵が街の中まで入り込んでくることはない(実機で敵が街エリアに侵入して見える不具合の修正)。
3. **気分**: エナジーの代わりに「普通/眠い/ご機嫌/お腹すいた/お金が欲しい」のいずれかの気分を持ち、時間で変化する。眠いと自分の家へ戻って休む。お腹がすくと街の「お店」へ行って基本食料を食べる。
4. **常に目的を持つ**: 優先順位は「弱った時の帰宅療養 > 依頼の遂行 > 持ち帰り中の荷物を家へ届ける > 空腹ならお店へ > 眠いなら帰宅 > (売る物があれば)お店で売却 > 性格による重み付き選択(戦う/採る/探検する/休む) > 川や池で息抜き、または目的地のある散歩」。何もすることがなくなる状態は存在しない。HPが最大値の30%以下(またはHP0)になると、他の何よりも優先して自分の家へ戻り、全回復するまで療養を続ける(全回復するまでは他の行動に戻らないため、弱ったまま戦闘へ舞い戻ってすぐまた弱るループは起きない)。HP0になった瞬間は「疲れたから帰る〜!」のような軽い一言を吹き出しで見せてから帰宅する演出になっている。
5. **鳥ごとの経済**: 採取・討伐・お宝で得た素材やゴールドは、まず鳥自身の個人所有物になる(`BirdState.gold` / `BirdState.inventory`、`useBirdEconomyStore`で永続化)。鳥は気分(特に「お金が欲しい」)や在庫を見て、自律的に街のお店まで歩いて行き、一番多く持っている素材を(1回の取引につき上限あり)プレイヤーに売る。プレイヤーが買い取れる分だけ購入され(所持ゴールドが足りない時は買える分だけ購入)、鳥は代金を受け取る。素材の持ち物合計には上限(`BIRD_INVENTORY_CAP`、現状150個)があり、実機報告(特定の素材を1000個近く持ち続け、行動効率に影響している様子)を受けて追加した——上限に達すると、普段は確率判定(`SELL_CHECK_CHANCE_BASE`/気分が「お金が欲しい」ならより高確率)で決めている売却トリップを、その場で必ず実行するようになる(`game/ai.ts`)。
6. **依頼掲示板**: 掲示板に同時に出せる依頼は最大3件(`MAX_ACTIVE_REQUESTS`)まで。プレイヤーはプリセット(`data/jobPresets.ts`のJOB_PRESETS)から依頼を選んで出す(満員の時は投稿不可、掲示板側にも「満員」表示が出る)。手が空いている鳥が、自分の性格・気分・報酬額から判断して受けるかどうかを決める(命令ではなく募集。受けてもらえないこともある)。達成すると報酬(ゴールド+経験値+街の発展ポイント+街評価)が対応した鳥・街にそれぞれ加算され、その枠は単に空く——以前はランダムなプリセットから新しい依頼が自動的に補充されていたが、これだと掲示板が常にランダムな依頼で埋まってしまい、プレイヤーが本当に出したい依頼を出せなくなる(実機報告)ため廃止した。依頼掲示板には対応者名と進捗(◯/◯)が表示される。依頼には4種類あり(`JobRequest.kind`)、それぞれ達成の仕方が異なる。採集・討伐の2種は、鳥が受注時・納品時にそれぞれ役場へ実際に足を運ぶ3段階の行動になっている(`BirdState.jobStage`: `toAccept`→役場へ受注に向かう、`working`→採集・討伐そのもの、`toDeliver`→役場へ納品に向かう。役場に着いた瞬間に初めて報酬・経験値が加算される)——実機フィードバックを受けて、受注・達成が一瞬のフラグ切り替えではなく実際のお使いとして表現されるようにした。採集依頼は、鳥がその場で必要素材を十分な数持っていれば(実機フィードバック:「鳥の在庫からも出せるようにしてほしい」)採取ポイントへ行かずにその場で納品分を確保でき、不足分だけ採取ポイントへ向かう。納品に向かっている間、掲示板には「(鳥の名前)が役場へ納品に向かっている」と表示される。
   - **採取**(`gather`): 指定した素材を指定数集める。受けた鳥が該当する資源を優先して自分で集めに行き、必要数に達するまで(1回で届かなければ何度でも)集め続ける。達成すると素材は直接プレイヤーの倉庫に入る(既存の唯一の依頼種別)。
   - **討伐**(`hunt`): 指定した種類の敵(スライム/コウモリ/オオカミ、名前が同じ個体はマップ上の複数体すべて対象)を指定数討伐する。受けた鳥はその種類の敵を優先して探して戦いに行き、実際に討伐に関わった回数が必要数に達すると達成(他の依頼と違い、進捗判定は毎ティックの戦闘解決後にまとめて行われる)。
   - **クラフト**(`craft`): 指定したアイテムを指定数、加工パネル(🛠️)で加工する。鳥の自律行動ではなくプレイヤー自身の加工操作がそのままカウントされる(受けている鳥は特に何もせず、通常通り自由に行動する——加工はプレイヤーの手作業であって鳥の仕事ではないため)。
   - **商人への納品**(`merchantDeliver`): 指定したアイテムを指定数、来訪中の商人に納品する。商人が来ていない間は進捗できず、掲示板に「商人の来訪を待っています…」と表示される。商人が来ている間、プレイヤーの倉庫に十分な在庫があれば「📦 納品する」ボタンで納品できる(在庫が足りない分は後から追加で納品可能)。
7. **戦闘・採掘・お宝**: 敵との戦闘・資源の採掘・お宝の開封は鳥が現地に到着すると自動で行われる(タップ操作は不要)。HPが最大値の30%以下(HP0を含む)になった鳥はその場で足踏みするのではなく自分の家まで戻り、全回復するまで療養する(消滅はない。全回復するまでは戦闘へ戻らない)。討伐報酬は、貢献したダメージ量に比例して関わった鳥たちに分配され、その一部(既定40%)が「治安協力金」としてプレイヤーの収入になる。お宝のゴールドは発見した鳥がそのまま受け取る。敵の頭上には⭐の数(1〜3個)でおおまかな強さの目安を常時表示する(`getEnemyStrengthTier`。HPと攻撃力から算出した相対的な強弱で、正確な数値までは出さない——実機フィードバックを受けて追加)。
7.5. **モンスタードロップ**: 敵を倒すと、種類ごとに設定された確率テーブルに応じて素材やアイテム(武器・防具・レア)がドロップし、参加した鳥の中からランダムに1羽がそれを手に入れる(鳥個人の持ち物になり、ステータスカードで確認できる)。
8. **持ち帰り**: 自由行動で採掘した素材は、その場で即座に手に入るのではなく、鳥が自分の家まで運んで帰ってから自分の所持品に加算される。運んでいる間は鳥の頭上に素材アイコンが表示される(依頼で集める素材は従来通り依頼達成時にプレイヤーへ直接加算)。
9. **リスポーン**: 倒した敵・採り切った資源・開けたお宝は一定時間後に元通り復活する(`src/game/config.ts`の`ENEMY_RESPAWN_MS`等で調整可)。世界が枯渇して止まることはない。
10. **見た目**: 淡いパステルカラー(空色・クリーム色・若草色)の可愛い放置ゲーム風の配色。カードやボタンには柔らかいドロップシャドウを、要所にピンクのアクセントを使用。4羽は公式イラストを加工した2頭身の本体スプライト(`assets/birds/{id}/base.png`、256×256・完全透過・共通アンカー)でマップ・ステータスカードに表示される。
11. **街の開拓**: 街の中心(町役場)を囲む土地があり、東西南北の内側4区画は最初から使える。内側2リング(24区画)はゴールド+素材で解放できる(遠い区画ほど高コスト)。さらに外周1リング(24区画、合計48区画)は、街レベルが3(町役場)に到達するまで解放を試みることすらできない——街の発展段階が進むほど、街エリア自体が実際に広がっていく。ロック中の区画をタップすると、解放に必要な「ゴールド」「素材の種類・数量」を現在の所持数と見比べられるモーダル(`PlotUnlockModal`)が開き、条件を満たしていれば「解放する」ボタンでその場で解放できる。解放済みで何も建っていない区画をタップすると建設メニュー(`ConstructionModal`)が開き、`data/buildingOptions.ts`のカタログ(道具屋の出張所・餌屋の出張所・武器屋・防具屋・花壇の5種)からゴールド+素材を払って選んで建てられる(建てた出張所・武器屋・防具屋をタップすると、既存店舗と在庫を共有する店舗モーダルが開く。花壇は装飾のみ)。ただし建設メニューが開くのは、その区画が現在の街エリアのゾーン楕円(次項参照)の内側にある場合のみ——土地の解放自体は外周のリング2・3でも街レベル条件さえ満たせば今まで通りできるが、建物を実際に建てられるのはゾーンがそこまで広がってからになる(`isInsideTownZone`)。ゾーンの外側をタップすると「🚧まだ街の外です」というモーダルが表示され、街が発展してゾーンが広がるのを待つよう促される。実機フィードバック(建設した建物がゾーンの外にはみ出て見え、「街を街として固めたい」との要望)を受けての制限。南北の区画には最初から実際に機能する「お店」が2つ建っている——南が🛠️道具屋(帽子・盾)、北が🌾餌屋(餌)。武器屋・防具屋はこの2つに含まれず、街のどこかに建設するまでは存在すらしない(次項参照)。どちらもタップするとまず店名・ジャンルのメニューが開き、「🛠️加工する」(その店のジャンルのレシピだけで加工)・「📦商品を並べる」(街の倉庫にある加工品をその店の棚に並べる)・「👀在庫を見る」(現在棚に並んでいる商品を見る)の3つから選べる。プレイヤーの主な行動サイクルは「鳥が素材を集める→プレイヤーが加工する→店へ商品を並べる→鳥が(または旅人が)購入する→売上が入る」。この2つの常設店舗は、街エリアのゾーン境界(次項参照)に対して十分な余白を持つ専用の座標(`townGrid.ts`のSHOP_AXIS_OFFSET)に固定配置されており、街レベルが上がって境界が広がっても常に内側に収まる。
11.5. **餌屋の仕入れ**: 餌屋のシード・粟穂・木の実・野菜は、加工品とは別枠で、NPC業者が街の資金を使って自動的に棚を補充する通常商品(街にコストが発生する仕入れ)。一方、既存の「初期の安価な餌(原価0で無料生成、街の資金は一切使わない)」は今回のアップデートでも仕様そのまま——鳥が空腹になると餌屋へ行き、棚に買える餌があればそれを購入(街の収入になる)、なければ従来通り無料の基本食で空腹を満たす(空腹は必ず解消される)。栄養ビスケット・高級ブレンド・元気ペレット・幸運のおやつは、加工で作れる高級餌(将来的な効果付与を見据えたデータ構造を用意済みだが、現状は効果未適用)。
11.6. **鳥の装備調達**: 鳥は自分の武器・防具・帽子・盾のいずれかが空いている時、時々そのカテゴリを扱う店の棚を確認し、買えるものがあれば自分のお金で購入する(1カテゴリにつき1つで十分と判断し、無限に買い続けたりはしない)。購入額は街の収入になる。帽子・盾は常設の道具屋で確認できるが、武器・防具は対応する店(武器屋・防具屋)が街のどこかに建設されるまでは確認自体が行われない——建設された場所は`data/townGrid.ts`のgetAllShopPositionsが街の区画を検索して見つけるので、どの区画に建てても鳥はちゃんと辿り着ける。

11.7. **役場の発展段階**: 街の発展ポイント(`useTownStore.developmentPoints`。土地解放1回につき30pt、建設1回につき20pt、依頼達成でも加算)が一定値に達するたび、役場は5段階で発展する——① ボロ役場🛖(0pt) → ② 村役場🏘️(60pt) → ③ 町役場🏛️(180pt) → ④ 自然保護局🌲(400pt) → ⑤ トロロ自然保護本部🏯(800pt)。段階が上がるたびに「🎊街が発展した!」のお祝いモーダルが表示され(「発展ポイントが◯◯に到達しました」と条件も明記)、マップ上の役場の絵文字・名前表示も切り替わる。役場自体をタップすると`TownStatusModal`が開き、現在の発展ポイントと次の段階までの残りポイントをいつでも確認できる。発展ポイントとは別に「街評価」(`reputation`)という人気度・知名度の指標も依頼達成のたびに独立して蓄積されるが、現状は数値を貯めるのみで実際の影響先(博物館・商人来訪頻度など)は未実装。

11.8. **街エリアと冒険フィールドのゾーン分け**: マップは「街エリア」(役場・建物・お店が集まる、くつろぎ・買い物の場)と「冒険フィールド」(採取ポイント・敵が点在する、活動の場)にはっきり分かれている。街エリアは役場を中心にした暖色の楕円形の背景と、点線の境界リングで視覚的に区切られ、街レベルが上がるほどこの楕円自体も少しずつ大きくなる(`data/townGrid.ts`のgetTownZoneRadius)。役場から4方向への簡易的な道(単色の帯)も表示される。鳥の「お腹すいた」「休憩したい」といった街エリア向けの用事(自由行動時の「探検」「休憩」)は街エリアの楕円の内側だけに、「採取したい」「討伐したい」は外側の冒険フィールド側だけに、それぞれの徘徊範囲が動的に収まるようになっている(`game/ai.ts`のrandomPointInField/randomPointNearTown)。冒険フィールド側も、森・鉱山・キノコ畑・湖・遺跡それぞれのエリアに、手描き風の地面タイル素材(`assets/tiles/`、`data/tileImages.ts`)を低透明度(0.32)で敷き詰めた背景パッチを敷いて緩やかなゾーニングを示している(森=濃い緑+小花、鉱山=岩混じりの草地、キノコ畑=クローバー、湖=青い小花、遺跡=土面)。各パッチは同系統のタイルを2種類ランダムに(ただし`WorldMap`の再描画のたびに変わらないよう、セル位置から決定的に計算した疑似乱数で)混ぜて敷いており、同じタイルが規則的に並ぶ格子模様に見えないようにしている。パッチの中央には「⛏️ 鉱山」のような小さなラベルを重ねて、何のゾーンかひと目でわかるようにした。街エリアの背景にも同系統の草地タイルをうっすら重ねている。タイルは水彩調で鳥キャラクターとは絵柄がやや異なるため、あくまで背景の低透明度テクスチャに留め、主張しすぎないよう調整してある。採掘ポイントなどの既存アイコンには軽いテキストシャドウを入れ、タイル背景の上に浮いて見えすぎないよう馴染ませている。街エリアの楕円は、既存の敵・採掘ポイントの配置と重ならないよう意図的に控えめなサイズに抑えてあるため(街の管理人の生活圏という「街の核」を示す表現であり、区画グリッドの外周を隙間なく覆う保証ではない)、遠方の土地区画の対角線上の角が楕円の外にはみ出すことがあるが、これは仕様。ロック中の未解放区画のうち、街レベルの条件をまだ満たしていないものは、金額表示の代わりに「Lv.◯」の必要レベルバッジと、通常より暗く落とした地面タイル背景(「未開拓」感の演出)で表示され、まだ購入を検討する段階にないことが一目で分かる(解放済みだが未着手の区画も同じ地面タイルを使い、殺風景さを解消している)。採掘ポイントの周りには土のくぼみタイルを1枚アクセントとして重ね、掘り跡らしさを添えている。街レベル3(町役場)に到達すると、街エリア(区画外周1リング)・冒険フィールド(奥地の鉱脈+強化されたオオカミの縄張り)の両方が同時に解放され、発展の実感と街レベルの意味づけが結びつくようにしてある。

11.9. **マップのパン・ズーム**: 区画総数が48に倍増したため、マップは画面サイズに合わせて縮小表示するのではなく、固定の「実サイズ」(`WorldMap`のWORLD_CANVAS_WIDTH/HEIGHT、900×1400)で描画される。指でドラッグして自由に移動でき、2本指のピンチで拡大・縮小できる(`components/PannableMap.tsx`、iOS標準のUIScrollViewズーム機能を利用。新規ライブラリの追加なし)。最小ズーム倍率は画面サイズから動的に計算され、街全体を見渡せる程度に自動調整される。アプリ起動時・街画面を開いた時は、常に役場が画面中央に来るように自動でスクロールされる(拡張された外周区画・奥地のフィールドはスクロールして初めて見える)。ミニマップや特定要素へのジャンプ機能は今回未対応。

(開発中、実機でマップ上のタップ・ドラッグが起動直後から一切反応しない不具合が発生し、一時的にこのズーム機能を疑って撤去したことがあったが、実際の原因は無関係な別バグ(次項参照)だったと判明したため、ズーム機能はそのまま復元済み。)
12. **鳥の家**: 4羽それぞれに専用の家が街の外周に1軒ずつあり、色で見分けられる。眠い気分になると、また採取した荷物を届けにも、自分の家に帰るようになった。
13. **街の管理人**: プレイヤーの分身として、町役場のそばに常駐するキャラクターがのんびり佇んでいる(操作はできない)。
14. **街の収益**: プレイヤーの収入源は — 討伐の治安協力金(討伐報酬の40%。クラフト素材・戦闘報酬のみが対象で、換金アイテムには一切適用されない)、鳥が街で基本食料を買う際の購入額(生成自体は常に無料でプレイヤーの資金は使わない)、時々街を訪れる「旅人」が倉庫の素材をランダムに買っていく分、鳥が餌屋・道具屋で実際に商品を購入した売上、そして鳥が商人に換金アイテムを売った際の折半分。それぞれ`PlayerState`の`tollFromHunt`/`tollFromFood`/`tollFromTraveler`/`tollFromShop`/`tollFromMerchant`に累計として記録される(実際に使える残高は`gold`で、これらは将来の帳簿UI向けの内訳)。唯一の経常的な支出は餌屋の商品仕入れ(`expenseFeedRestock`)で、仕入れ値より高く売れる分だけ純利益になる。鳥が売りに来る1回の取引でプレイヤーが支払える金額には上限(`SELL_MAX_GOLD_PER_TRIP`)があり、治安協力金などの収入が単発の売買で食いつぶされて残高が伸び悩まないようにしてある。旅人の来訪チェック頻度(`TRAVELER_CHECK_CHANCE`)は、以前は商人の来訪チェックの約7倍・鳥が街に素材を売る頻度をも上回る値になっており、実機で11時間オフラインにした際に街の素材倉庫が完全にゼロになる不具合の原因になっていた——商人と同程度の頻度まで引き下げ、旅人はあくまで「たまに立ち寄る」flavor程度の存在に留めた。
15. **経験値とレベルアップ**: 討伐に参加した(ダメージを与えた)鳥は敵の種類に応じた経験値を得る(雑魚5〜7exp、やや強い敵ほど多い。分配ではなく参加者全員が満額)。一定量たまるとレベルアップし、攻撃力・HP・防御力・素早さが少し上がる。レベルアップは生活ログにも記録される。以前は攻撃力・HPの上昇分が`BirdWallet`に永続化されておらず、アプリを再起動するたびキャラクター素の初期値まで戻ってしまっていた(防御力・素早さだけは永続化されていたため、レベルが高いのに攻撃力・HPだけ低いままに見える実機報告の原因)——`BirdWallet`に`atk`/`maxHp`を追加し、他の2ステータス同様に永続化するよう修正。修正前からの既存セーブも、記録済みのレベルに応じた分だけ攻撃力・HPを遡って補正して引き継がれる(`useBirdEconomyStore`のgetWalletが担う)。ただし`useGameTimeStore`のオフライン追いつき計算(catchUpOffline)だけはこの補正を経ない生の`wallets`を直接読んでいたため、その1回だけ`undefined + 上昇量`が計算されて攻撃力・HPが`NaN`のまま永続化されてしまう不具合が上記の修正直後に発生した(実機報告)。catchUpOfflineもgetWallet経由(getAllWallets)で読むよう修正し、既にNaNになってしまったセーブも次回起動時に自動で復旧するようにした——のはずが、`JSON.stringify(NaN)`は`null`にシリアライズされる(NaNのままではない)ため、AsyncStorageに一度書き込まれたNaNは次回読み込み時には`null`として復元され、`Number.isNaN`チェックをすり抜けてしまっていた。`null + 上昇量`はJSでは0扱いで計算されてしまうため、レベル相応の値ではなく「0からわずかに上昇しただけ」の極端に低い攻撃力・HPになる(実機報告: 攻撃力・HPが激弱に)というさらなる副作用を生んでいた。`Number.isFinite`によるチェックに変更し、undefined/null/NaN/Infinityのいずれも一括して補正対象にするよう修正した——それでもなお1羽だけ、レベル86でHP15/攻撃力6という、キャラクター自身のレベル1初期値(HP70/攻撃力10)より低い値のまま治らない実機報告があった。これは一連の中間的な壊れ方のどこかで、Number.isFiniteでは検知できない「有限だが不合理に低い」値が一度persisted状態に書き込まれてしまったケースと考えられる。atk/maxHpはgrantExpの`+=`でしか増えないため、defense/speedと全く同じ回数だけ増えているはずで、「自身のレベル1初期値を下回っている」こと自体が、原因を特定できずとも壊れている確実な証拠になる——この不変条件(自身のbase値を下回っていたら補正)もチェックに追加し、原因の詳細を特定できていなくても今後同種の破損が起きれば毎回自己修復されるようにした。
15.5. **鳥ごとの基礎ステータス**: HP・攻撃力・防御力・素早さ・運の5つを個体ごとに保持(キャラクターごとに初期値が異なる)。素早さ・運は将来の移動速度差・ドロップ運への拡張を見込んで用意済みだが、現状は表示のみで挙動には未反映。満腹度・ご機嫌度も数値(0〜100)で保持し、既存の気分テキスト(「お腹すいた」等)と連動する — 満腹度は毎ティック減っていき、閾値を下回ると自動的に「お腹すいた」になる(ランダム抽選ではなく実際の空腹に基づく)。食事すると満腹度は全回復する。ご機嫌度はご機嫌/空腹の状態に応じて緩やかに増減する。
15.6. **装備**: 武器・防具・帽子・盾の4スロットを鳥ごとに持つ。帽子・盾は常設の道具屋で、武器・防具はそれぞれ専用に建設した武器屋・防具屋で買う(またはモンスターから武器・防具をドロップで入手する)と、対応するスロットが空いていれば自動的に装備される(上書きはしない。同じ種類の2つ目は持ち物として温存)。装備には攻撃力・防御力のボーナスがあり、実際の戦闘ダメージ・被ダメージ軽減に反映される。見た目の変化は今回は実装せず、`ItemDef.spriteVariant`という未使用フィールドだけ用意してある(将来、装備で見た目が変わる拡張をしやすくするため)。
15.7. **換金アイテムと商人**: 宝石・金塊・王家の宝飾品などの「換金専用アイテム」(`ItemDef.itemType: 'convertible'`)は、加工には使えず街の倉庫にも入らない、鳥個人が持つだけの純粋な資産。討伐・採掘の低確率ドロップでのみ入手できる(討伐報酬の治安協力金は一切適用されない)。街には時々(数分〜十数分に一度)「商人」が現れ、数分間だけ簡易的な店を構える。商人が滞在している間、鳥は自分の判断で ①持っている換金アイテムを商人に売る(代金は鳥50%/街50%で折半——「市場利用料」という名目で`tollFromMerchant`に計上)、②商人がその来訪ごとにランダムに用意した棚(通常アイテム中心・低確率でレア品)から欲しい物を自分のお金で買う(この代金は街の収入にはならない)、の両方を行いうる。プレイヤー側は🏕️アイコンをタップすると、残り時間と棚の中身を確認できる(閲覧のみ・取引は基本的に鳥に任せる)。唯一の例外が「倉庫の素材を売る」欄で、街の倉庫(`PlayerState.materials`)にある素材はどの鳥の持ち物でもなくプレイヤー(街)自身のものなので、旅人のランダム購入や鳥の自律売買を待たずに、商人の来訪中ならいつでもプレイヤーの意思でその場で売却できる(`sellMaterialToMerchant`。他の素材売却と同じ単価=`MATERIAL_SELL_PRICE`)。売却個数は+/-ボタン(10個刻み)で選んで指定できるほか、「全部売る」ボタンでまとめて売ることもできる——以前は在庫を丸ごと一括売却する仕様だったが、必要な素材までうっかり全部売ってしまう実機報告を受けて個数指定に変更した。旅人(街の在庫を一過性で消費し代金が街の収入になる)とは役割が完全に分離しており、`WorldState.merchant`として別データで管理される。
16. **生活ログ**: 画面下部に、採集・討伐(誰が倒して報酬がどう分配されたか)・売却・購入・依頼達成・旅人の来訪・レベルアップなど、直近10件の出来事が「誰が・何をして・どうなったか」が分かる一文で常時表示される。
17. **鳥ごとのステータスカード**: 🐦ボタン(または鳥をタップ)で、4羽それぞれの名前・レベル・経験値・所持ゴールド・持ち物・数値ステータス(HP/攻撃力/防御力/素早さ/運、装備ボーナス込み)・満腹度/ご機嫌度・現在の装備4スロット・現在の状態(採集中/討伐中/売却中/購入中/休憩中など)・現在の目的が見られるカード一覧を開ける。
18. **ステータス表示**: 画面上部には所持ゴールドと、鳥のようす(🐦)・加工(🛠️)・倉庫(🎒)を開くボタンのみを常時表示(全素材の常時表示はしない)。プレイヤーの所持品は倉庫画面で、鳥の所持品(素材+モンスタードロップのアイテム)はステータスカードで確認する。
19. **加工(プレイヤーの主な行動)**: 🛠️ボタンから、街の倉庫にある素材を消費してアイテム(武器・防具・レアの3種)を1つずつ作れる。必要素材が足りないレシピはボタンが押せない。加工品は街の倉庫(`PlayerState.items`)に貯まり、お店の品揃えに反映される。全レシピのうち最初から使えるのは3個(レザーハット・木の盾・栄養ビスケット)のみ(`CraftingRecipe.unlockedByDefault`)で、残りは加工パネルにそもそも表示されない。未解放レシピは次の4ルートのいずれかで入手でき、入手済みかどうかは`useRecipeStore`(永続化)が管理する: ①商人が滞在中にランダムで1つ「レシピの提供」として提示し、ゴールドを払って購入(`MerchantModal`の📜欄、購入は`buyMerchantRecipe`)、②鳥が採取を完了するたびに低確率でお土産として発見(`RECIPE_GIFT_CHANCE`)、③依頼掲示板の依頼(討伐・クラフトなど)を達成した時の低確率報酬(`RECIPE_QUEST_CHANCE`)、④モンスターを倒した時の低確率報酬(`RECIPE_COMBAT_CHANCE`)。いずれの場合も新規レシピを1つ得るたびに`RecipeUnlockModal`(「📜新しいレシピを手に入れた!」)が表示される。`usePlayerStore.craftItem`は未解放レシピでの加工をデータ層でも拒否する(UIボタンを隠すだけでなく)。
20. **永続化**: プレイヤーの所持ゴールド・素材(14種)・加工品・収入内訳、街の土地の解放状況・建物、そして各鳥の個人ゴールド・所持素材・持ち物(ドロップ品)・レベル・経験値は端末に保存(AsyncStorage)。フィールド上の鳥の位置・気分・依頼・生活ログは現状セッション内のみ(今後の課題)。
21. **ゲーム内時間とオフライン進行**: アプリを開いている間、ゲーム内カレンダー(`gameTimeMs`)は現実より60倍速で進む(現実1分≒ゲーム内1時間、`ONLINE_TIME_SCALE`)。ただし現状はティックベースの各種処理(リスポーン・商人の滞在時間など)はこの数値に連動しておらず、あくまで将来のシステム(街レベル・クエスト期限など)向けの土台。アプリを閉じていた間は、次回起動時に前回終了時刻からの経過時間をまとめて計算し反映する(最大8時間分でキャップ、それ以上閉じていてもキャップ分しか進行しない)。この「追いつき計算」は1ティックずつ再現するのではなく、性格ごとに実測した「1討伐/1採取にかかる平均ティック数」を使った概算(`OFFLINE_TICKS_PER_KILL`/`OFFLINE_TICKS_PER_GATHER`、`game/offlineProgress.ts`)で、実際に起動し続けた場合と釣り合うよう調整済み(討伐報酬の治安協力金・旅人の来訪に加えて、鳥が集めた素材を街のお店に売る自律売買もオンライン同様の頻度で概算再現し、代金分プレイヤーの所持ゴールドを減らして街の倉庫に素材を加算する。餌屋の仕入れ・商人の来訪・依頼はオフライン中は簡略化のため考慮しない)。集めた素材のうちどれだけが実際に街の倉庫入りしたか(自律売買で売れた分。旅人がその後買っていく分と相殺されることもある)は「おかえりレポート」モーダルに内訳として表示される。起動時には計算結果を「おかえりレポート」モーダルで表示する(経過時間・街の収入内訳・鳥ごとの獲得ゴールド/素材/レベルアップ・一言ハイライト)。

### 事前準備(iPhone側、1回だけ)

- App Store から **Expo Go** アプリをインストール

### 起動して確認するたび

1. PCとiPhoneを**同じWi-Fi**に接続する
2. PCでプロジェクトフォルダに入り、開発サーバーを起動

   ```bash
   npx expo start
   ```

3. ターミナルにQRコードが表示されるので、iPhoneの**カメラアプリ**でスキャン → 「Expo Goで開く」の通知をタップ
4. Expo Goが起動し、アプリが実機で動きます

コードを変更して保存すると、実機側は自動でリロードされます(Fast Refresh)。確認が終わったらターミナルで `Ctrl+C` して開発サーバーを止めればOKです。

### うまくいかない時

- QRコードが読み取れない/繋がらない → PCとiPhoneが同じWi-Fiか確認。会社・大学のWi-Fiなど端末間通信が制限されたネットワークでは失敗しやすいので、自宅Wi-Fiや共有したスマホのテザリングを試す
- それでも繋がらない → `npx expo start --tunnel` (別ネットワークでも動くが、初回に `@expo/ngrok` の自動インストールを求められます)

    useQuestStore.ts        永続化される達成済みマイルストーンの集合(completed: Record<string, boolean>)（zustand + AsyncStorage。ハクの加入クエスト・モネの討伐マイルストーンなど、今後のクエストにも使い回せる汎用の仕組み）

## EAS Build / Submit（iOS / App Store）

このプロトタイプは iOS 向けに EAS Build でビルドし、EAS Submit で App Store Connect に提出できる構成になっています。

### 前提条件

- Apple Developer Program のメンバーシップ
- `eas-cli` をインストールしてログイン: `npm install -g eas-cli && eas login`
- Expo アカウントでプロジェクトを初期化: `eas init`（`app.json` の `extra.eas.projectId` が自動更新されます）

### 置き換えが必要なプレースホルダー

- `app.json` → `expo.ios.bundleIdentifier`: 実際に使う Bundle ID に変更（App Store Connect で登録したものと一致させる）
- `app.json` → `expo.extra.eas.projectId`: `eas init` 実行後に自動で入る値
- `eas.json` → `submit.production.ios`:
  - `appleId`: Apple Developer アカウントのメールアドレス
  - `ascAppId`: App Store Connect 上のアプリの Apple ID（数字）
  - `appleTeamId`: Apple Developer Team ID

`eas submit` はインタラクティブに App Store Connect API キーでの認証も選択できます（`eas.json` に値を埋めずにコマンド実行時のプロンプトに従う方法でも可）。

### ビルド & 提出コマンド

```bash
# シミュレータ確認用ビルド
eas build --platform ios --profile preview

# 本番ビルド（App Store 提出用）
eas build --platform ios --profile production

# App Store Connect (TestFlight) へ提出
eas submit --platform ios --profile production --latest
```
