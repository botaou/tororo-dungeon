# トロロの街 (prototype)

街の管理人・工房の店主としてコザクラインコたちの暮らしを眺める箱庭シム。Expo SDK 54 (React Native) + TypeScript。Expo Go(SDK 54対応版)でそのまま実機確認できます。

プレイヤーは鳥を直接操作しません。中央の街と周囲のフィールド(敵・採掘資源・お宝)を4羽が各々の意思で歩き回ります。**素材・お金はまず鳥個人の所有物になり**、プレイヤーは街の管理人・商人として、鳥から素材を買い取ったり、依頼掲示板で欲しい素材を発注したりして、街の共有資源(倉庫)を少しずつ蓄えます。

## ゲームループ

1. **街とフィールド**: マップ中央に街、その周りに森・鉱山・キノコ畑・湖・遺跡といった自然な区画があり、それぞれのエリア専用の素材(森=木材/木の実/薬草/羽根、鉱山=鉱石/宝石/石炭、キノコ畑=キノコ、湖=魚/真珠/水草、遺跡=遺物/魔石/古いコイン)が手配置される、常設の1つのマップ(ステージ制ではない)。街の周囲には木や花の装飾も配置される。
2. **個体AI(性格は重み付け、絶対ではない)**: 4羽はそれぞれ独立したAIで行動する(1つの群れとして固まらない)。戦闘・採掘・探索・休憩のどれも全員が行いうるが、性格によって選ばれやすさと危険地帯への忌避度が変わる。
   - 🟢 トロロ(vanguard): 戦闘・探索に大きく偏るが、採掘や休憩もする。危険は気にしない。
   - 💛 ビビ(clingy): 休憩・探索を好むが、戦闘や採掘もする。危険は苦手。
   - 🩵 ハク(cautious): 休憩に大きく偏るが、危険度の低い相手となら普通に戦う。
   - ✨ モネ(freeSpirit): 採掘・お宝回収に大きく偏るが(納品+20%)、資源が無ければ戦闘や探索もする。
   - 敵と遭遇した際の戦闘選択率は、その敵の強さ(攻撃力)と各鳥の危険忌避度に応じて下がる(弱い敵ならほぼ誰でも戦う)。
   - 複数の鳥が重なりそうになると、毎ティック軽く押し合ってすれ違う(`separateBirds`)。
3. **気分**: エナジーの代わりに「普通/眠い/ご機嫌/お腹すいた/お金が欲しい」のいずれかの気分を持ち、時間で変化する。眠いと自分の家へ戻って休む。お腹がすくと街の「お店」へ行って基本食料を食べる(これは常にプレイヤーの資金を使わず無料で提供される)。鳥をタップすると今の気分・一言・その鳥自身の所持ゴールドと素材が見られる。
4. **常に目的を持つ**: 優先順位は「気絶からの回復 > 依頼の遂行 > 持ち帰り中の荷物を家へ届ける > 空腹ならお店へ > 眠いなら帰宅 > (売る物があれば)お店で売却 > 性格による重み付き選択(戦う/採る/探検する/休む) > 川や池で息抜き、または目的地のある散歩」。何もすることがなくなる状態は存在しない。
5. **鳥ごとの経済**: 採取・討伐・お宝で得た素材やゴールドは、まず鳥自身の個人所有物になる(`BirdState.gold` / `BirdState.inventory`、`useBirdEconomyStore`で永続化)。鳥は気分(特に「お金が欲しい」)や在庫を見て、自律的に街のお店まで歩いて行き、一番多く持っている素材を(1回の取引につき上限あり)プレイヤーに売る。プレイヤーが買い取れる分だけ購入され(所持ゴールドが足りない時は買える分だけ購入)、鳥は代金を受け取る。
6. **依頼掲示板**: プレイヤーが欲しい素材・数量・報酬(ゴールド)を指定して依頼を出す。手が空いている鳥が、自分の性格・気分・報酬額から判断して受けるかどうかを決める(命令ではなく募集。受けてもらえないこともある)。依頼を受けた鳥は該当する資源を優先して集め、完了すると素材は直接プレイヤーの倉庫に入り、報酬ゴールドは鳥自身の懐に入る。
7. **戦闘・採掘・お宝**: 敵との戦闘・資源の採掘・お宝の開封は鳥が現地に到着すると自動で行われる(タップ操作は不要)。倒れた鳥はその場でしばらく休むと自然回復する(消滅・全滅はない)。討伐報酬は、貢献したダメージ量に比例して関わった鳥たちに分配され、その一部(既定30%)が「治安協力金」としてプレイヤーの収入になる。お宝のゴールドは発見した鳥がそのまま受け取る。
8. **持ち帰り**: 自由行動で採掘した素材は、その場で即座に手に入るのではなく、鳥が自分の家まで運んで帰ってから自分の所持品に加算される。運んでいる間は鳥の頭上に素材アイコンが表示される(依頼で集める素材は従来通り依頼達成時にプレイヤーへ直接加算)。
9. **リスポーン**: 倒した敵・採り切った資源・開けたお宝は一定時間後に元通り復活する(`src/game/config.ts`の`ENEMY_RESPAWN_MS`等で調整可)。世界が枯渇して止まることはない。
10. **見た目**: 淡いパステルカラー(空色・クリーム色・若草色)の可愛い放置ゲーム風の配色。カードやボタンには柔らかいドロップシャドウを、要所にピンクのアクセントを使用。
11. **街の開拓**: 街の中心(町役場)を囲む24区画の土地があり、東西南北の内側4区画は最初から使える。残り(斜め4区画+外周16区画)はロックされていて、ゴールド+素材で解放できる(遠い区画ほど高コスト)。解放した土地はタップすると工房/店/倉庫のいずれかを配置できる(見た目のみで、まだ機能はない)。南側の区画には最初から実際に機能する「お店」が1つ建っている(鳥たちが売買に使う。プレイヤーがタップすると開くが、クラフト等はまだ準備中)。
12. **鳥の家**: 4羽それぞれに専用の家が街の外周に1軒ずつあり、色で見分けられる。眠い気分になると、また採取した荷物を届けにも、自分の家に帰るようになった。
13. **街の管理人**: プレイヤーの分身として、町役場のそばに常駐するキャラクターがのんびり佇んでいる(操作はできない)。
14. **ステータス表示**: 画面上部には所持ゴールドと倉庫を開くボタンのみを常時表示(全素材の常時表示はしない)。プレイヤーの所持品は倉庫画面(🎒ボタン)で確認する。鳥の所持品は、その鳥をタップした時だけ吹き出しに表示される。
15. **永続化**: プレイヤーの所持ゴールド・素材(14種)、街の土地の解放状況・建物、そして各鳥の個人ゴールド・所持素材は端末に保存(AsyncStorage)。フィールド上の鳥の位置・気分・依頼は現状セッション内のみ(今後の課題)。

## セットアップ(PCで実機のiPhone確認)

Expo Go を使えば、Xcode も Apple Developer 登録も不要でiPhone実機に反映して試せます。

### 事前準備(PC側、1回だけ)

1. **Node.js** をインストール(LTS版。 https://nodejs.org/ )
   - 確認: `node -v` でバージョンが表示されればOK
2. **git** をインストール(https://git-scm.com/ )
3. このリポジトリを clone

   ```bash
   git clone https://github.com/botaou/tororo-dungeon.git
   cd tororo-dungeon
   git checkout claude/idle-dungeon-game-prototype-pj9axt
   ```

4. 依存パッケージをインストール

   ```bash
   npm install
   ```

### 事前準備(iPhone側、1回だけ)

- App Store から **Expo Go** アプリをインストール

### 起動して確認するたび

1. PCとiPhoneを**同じWi-Fi**に接続する
2. PCでプロジェクトフォルダに入り、開発サーバーを起動

   ```bash
   npx expo start
   ```

3. ターミナルにQRコードが表示されるので、iPhoneの**カメラアプリ**でスキャン → 「Expo Goで開く」の通知をタップ
4. Expo Goが起動し、アプリが実機で動きます

コードを変更して保存すると、実機側は自動でリロードされます(Fast Refresh)。確認が終わったらターミナルで `Ctrl+C` して開発サーバーを止めればOKです。

### うまくいかない時

- QRコードが読み取れない/繋がらない → PCとiPhoneが同じWi-Fiか確認。会社・大学のWi-Fiなど端末間通信が制限されたネットワークでは失敗しやすいので、自宅Wi-Fiや共有したスマホのテザリングを試す
- それでも繋がらない → `npx expo start --tunnel` (別ネットワークでも動くが、初回に `@expo/ngrok` の自動インストールを求められます)

## コード構成

```
src/
  types.ts              共有の型定義（BirdState, JobRequest, WorldState, TownPlotDef など）
  data/
    characters.ts       4羽の性格・ステータス定義
    world.ts             街の位置、敵・採掘・お宝の定義（常設フィールド）
    materials.ts          素材ID→ラベル・アイコンの対応表
    marketPrices.ts        鳥から素材を買い取る際の固定レート表
    townGrid.ts           街の土地グリッド（24区画）の位置・解放コスト定義、常設ショップの区画ID
    houses.ts              鳥ごとの家の位置
    moods.ts              気分の定義とランダム抽選
  game/
    config.ts            移動速度・気分更新間隔・治安協力金の割合などの定数
    ai.ts                各鳥の独立AI（性格ごとの自由行動・依頼遂行・自律売買ロジック）
    requests.ts           依頼を受けるかどうかのスコアリング
    combat.ts             自動戦闘の解決ロジック（貢献ダメージ比例の報酬分配、純粋関数）
    thoughts.ts            鳥をタップした時の一言セリフ
    useGameClock.ts       1秒間隔のグローバルティック
  store/
    usePlayerStore.ts     永続化される所持ゴールド・素材（zustand + AsyncStorage、街の共有倉庫）
    useWorldStore.ts      常設ワールドの状態と毎ティックのAI駆動（非永続）
    useTownStore.ts        永続化される街の土地の解放状況・建物（zustand + AsyncStorage）
    useBirdEconomyStore.ts 永続化される鳥ごとの個人ゴールド・所持素材（zustand + AsyncStorage）
  screens/
    TownScreen.tsx        唯一のメイン画面（マップ+最小限のUI）
  components/
    WorldMap.tsx           街・フィールド・鳥・土地区画・家・店主の描画
    RequestBoard.tsx        依頼掲示板のモーダル
    ShopModal.tsx           お店のモーダル（鳥の自律売買は裏で進行。プレイヤー向け機能は準備中）
    PlayerInventoryModal.tsx プレイヤーの倉庫（ゴールド・全素材）を表示するモーダル
```

## EAS Build / Submit（iOS / App Store）

このプロトタイプは iOS 向けに EAS Build でビルドし、EAS Submit で App Store Connect に提出できる構成になっています。

### 前提条件

- Apple Developer Program のメンバーシップ
- `eas-cli` をインストールしてログイン: `npm install -g eas-cli && eas login`
- Expo アカウントでプロジェクトを初期化: `eas init`（`app.json` の `extra.eas.projectId` が自動更新されます）

### 置き換えが必要なプレースホルダー

- `app.json` → `expo.ios.bundleIdentifier`: 実際に使う Bundle ID に変更（App Store Connect で登録したものと一致させる）
- `app.json` → `expo.extra.eas.projectId`: `eas init` 実行後に自動で入る値
- `eas.json` → `submit.production.ios`:
  - `appleId`: Apple Developer アカウントのメールアドレス
  - `ascAppId`: App Store Connect 上のアプリの Apple ID（数字）
  - `appleTeamId`: Apple Developer Team ID

`eas submit` はインタラクティブに App Store Connect API キーでの認証も選択できます（`eas.json` に値を埋めずにコマンド実行時のプロンプトに従う方法でも可）。

### ビルド & 提出コマンド

```bash
# シミュレータ確認用ビルド
eas build --platform ios --profile preview

# 本番ビルド（App Store 提出用）
eas build --platform ios --profile production

# App Store Connect (TestFlight) へ提出
eas submit --platform ios --profile production --latest
```
